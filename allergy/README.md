# 緊急アレルギー情報カード (GitHub Pages版・サーバー不要)

入力した情報を **URLの「#」以降** に小さく詰めて埋め込み、そのURLをNFCタグに書き込む方式です。
サーバーもデータベースも使いません。

## なぜ個人情報がGitHubに残らないのか

- 情報はタグに書き込むURLの `#` 以降にだけ入ります。`#` 以降はブラウザの中だけで処理され、
  サーバー(GitHub)には送信されません。
- このリポジトリに入っているのは「画面を作るコード」だけで、誰の情報も含みません。
  公開リポジトリにしても問題ありません。
- ページは外部通信を一切しません(CSPで `connect-src 'none'`)。

## 公開手順(GitHub Pages)

1. GitHubで新しいリポジトリを作る(例: `allergy-card`)。
2. このフォルダの中身(`index.html` `app.js` `codec.js` `kanji-table.js` `style.css` `.nojekyll`)をアップロードする。
   `tools/` と `README.md` は置いても置かなくても動きます。
3. リポジトリの **Settings → Pages → Build and deployment** で
   `Deploy from a branch` / `main` / `/ (root)` を選んで保存する。
4. 数分後に `https://ユーザー名.github.io/allergy-card/` で開けるようになる。

## 使い方

1. 公開したページを開き、情報を入力する。下に **NFCタグに書き込むURL** が自動で作られる。
2. 「タグの種類」を選ぶと、容量メーターが実際のタグに合わせて動く。
3. Android版Chromeなら「NFCタグに書き込む」ボタンで直接書き込める(未検証機能)。
   それ以外は「URLをコピー」して NFC Tools などのアプリで書き込む。
4. 書き込んだら、別のスマホでかざして表示を確認する。
5. 確認できたら、必要に応じてタグをロック(読み取り専用化)する。

内容を変えたいときは、タグをかざして開いたページの右上「編集する」から直し、
新しいURLをタグに書き直す(ロック済みのタグは書き直せません)。

## どうやって小さくしているか(形式v2)

| 工夫 | 効果 |
|---|---|
| ひらがな・カタカナ・英数字を **1バイト** で表す(UTF-8では かなが3バイト) | 文章がおよそ半分以下に |
| 漢字(JIS第1・第2水準 6355字)を **2バイト** で表す(UTF-8では3バイト) | 漢字が約1/3減 |
| 電話番号を **1桁=4ビット** で表す | 11桁が6バイト |
| アレルゲン28品目は **1項目=1バイト**(番号+重症度) | 自由入力より大幅に節約 |
| 入力のない項目は書かない(最初の1バイトに有無をまとめる) | 空欄の分がゼロ |
| JSONの記号(`[` `"` `,`)を使わない | 約30バイト減 |
| さらにdeflate圧縮した方が短ければそちらを使う | 長文のとき少し得 |

実測(NTAG215 / 504バイト品、`https://username.github.io/allergy-card/` の場合):

| 内容 | 旧形式 | 新形式 |
|---|---|---|
| 標準的な入力(連絡先2件・アレルゲン4件・短いメモ) | 317バイト | **195バイト** |
| 同じ入力に足せる症状メモの量 | 約95文字 | **約180文字** |
| 定義済み28品目すべて + 標準入力 | 346バイト | **209バイト** |
| 最小構成 | 98バイト | **65バイト** |

旧形式(`#1…` `#0…`)で書き込んだタグも、そのまま読めます。

さらに空きを増やすには:

- **リポジトリ名を短くする**(`allergy-card` → `c` など)。`ユーザー名.github.io` というリポジトリを作ると、
  パスなしの `https://ユーザー名.github.io/#…` になり、約13バイト減ります。独自の短いドメインならもっと減ります。
- **NTAG216(888バイト)** のタグに替える。1枚あたりの値段差は小さいです。
- アレルゲンは入力欄の候補から選ぶ(候補にない名前は自由入力扱いになり、1項目あたり数バイト増えます)。

## タグの種類と容量

| タグ | NDEFの実質容量 |
|---|---|
| NTAG213 | 約137バイト |
| NTAG215 | 約492バイト(504バイト品) |
| NTAG216 | 約868バイト |

メーターは「`https://` が1バイトに圧縮される」前提の見積もりです。アプリによってはこの圧縮をしないため、
余裕が少ないときは入らない場合があります。

## 注意(この方式の限界とセキュリティ)

- **URLそのものが情報です。** SNS・メール・GitHubのIssueやREADMEなどに貼らないでください。
  スマホのブラウザ履歴にも残ります。
- **タグを読み取れる人は誰でも内容が見えます。** 載せる情報は最小限に(続柄、住所は載せない等)。
- **更新にはタグの書き直しが必要です。** ロックすると改ざんは防げますが、書き直せなくなります。
- **偽タグへのすり替え**は、ソフトでは防げません。改ざん検知シールの併用を推奨します。
- GitHub Pagesはレスポンスヘッダーを設定できないため、CSPは `<meta>` で指定しています。
- **次の2つは変更禁止です。** すでに書き込んだタグの表示が壊れます。
  - `codec.js` の `PRESETS`(定義済みアレルゲン)は **末尾に足すだけ**(上限42個)
  - `kanji-table.js` の並び(`tools/gen-kanji-table.js` で生成。漢字の番号になっている)

## ファイル構成

```
index.html        画面(閲覧・入力・URL生成)
app.js            画面の動き
codec.js          データ ⇔ URLの変換(圧縮)
kanji-table.js    漢字の番号表(JIS X 0208 の漢字6355字)。ブラウザの機能に頼らないための同梱
style.css         見た目
.nojekyll         GitHub Pagesでそのまま配信するための空ファイル
tools/            kanji-table.js を作るスクリプト(サイトの動作には不要)
```
